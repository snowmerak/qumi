# Qumi

Q Gateway에 연결하는 Chrome Manifest V3 사이드 패널 확장입니다. Gateway 연결과 모델 선택, 스트리밍 채팅, 도구 호출을 처리할 수 있는 TypeScript 에이전트 루프, 긴 문맥 압축을 제공합니다. UI는 `merak-protocol-design-system`의 CSS를 사용합니다.

## 실행

1. Q에서 `q gateway start`를 실행하고 출력된 `http://127.0.0.1:<port>/v1` 주소를 확인합니다. API 키를 설정했다면 키도 준비합니다.
2. 이 디렉터리에서 `pnpm install`과 `pnpm build`를 실행합니다.
3. Chrome의 `chrome://extensions`에서 개발자 모드를 켜고 `dist` 폴더를 압축 해제된 확장 프로그램으로 로드합니다.
4. 웹페이지에서 Qumi 아이콘을 클릭해 사이드 패널을 열고 Gateway 주소, API 키(필요할 때만), 모델과 모델 API를 설정합니다. 모델 목록에 문맥 길이가 없으면 토큰 수를 직접 입력합니다.

5. Qumi의 모든 HTTP(S) 사이트 접근 권한을 브라우저에서 허용하면, 웹페이지 로드 완료 후 현재 탭에 자동 연결됩니다. 탭 전환이나 다른 사이트로 이동해도 다시 연결됩니다. 브라우저가 Qumi의 사이트 접근을 제한했다면 `현재 페이지`의 **연결**을 눌러 해당 사이트 권한을 요청할 수 있습니다. 페이지 질문을 하면 모델이 URL·제목·본문 읽기 도구를 호출할 수 있습니다. `dom_list`는 `body`부터 시작해 보이는 자식 요소와 고유 CSS 선택자를 반환하고, `dom_read`는 선택한 요소의 내용·직접 자식 텍스트 노드·속성을 읽습니다. `scroll_all_text`는 페이지의 보이는 텍스트 노드를 문서 순서대로 한 번에 읽습니다. `dom_write`는 `textNodeIndex`로 본문 문구를 바꾸고, 입력값과 허용된 HTML 속성도 변경합니다. 속성 제거에는 `value: null`을 사용합니다. URL 이동, 새 탭 열기, 기존 탭 전환도 지원합니다.

사이드 패널은 기본적으로 브라우저 언어에 맞춰 영어·한국어·일본어·중국어(간체)로 표시됩니다. 설정의 **언어**에서 직접 고르면 Gateway 연결 전에도 즉시 적용되고 다음 실행에도 유지됩니다.

설정의 **MCP 서버**에서 Streamable HTTP 엔드포인트의 이름과 URL을 등록합니다. 인증 방식은 요청 헤더(JSON) 또는 OAuth를 선택할 수 있습니다. OAuth에서는 서버에 등록된 공개 클라이언트 ID, 공개 Client ID Metadata Document URL을 입력하거나 둘 다 비워 동적 클라이언트 등록을 시도합니다. 서버를 추가한 뒤 **로그인**을 누르면 Chrome 로그인 창에서 Authorization Code + PKCE를 진행합니다. 로그인이 끝나면 설정을 저장하세요. **연결 확인**은 서버의 도구 목록을 조회하며, 저장 후 대화 턴을 시작하면 등록된 서버의 도구가 `mcp_<서버 이름>__<도구 이름>` 형식으로 모델에 제공됩니다. Qumi는 MCP 2026-07-28 서버와 초기화 세션을 쓰는 2025-11-25 서버를 연결합니다. MCP 도구 호출에는 **브라우저 작업 확인** 설정의 변경 작업 정책이 적용됩니다.

OAuth 토큰과 동적 등록 정보는 `chrome.storage.session`에만 저장되므로 브라우저를 다시 열면 로그인이 필요합니다. 수동 요청 헤더는 기존처럼 확장 로컬 저장소에 보관됩니다. OAuth 리다이렉트 주소는 확장 ID에 따라 `chrome.identity.getRedirectURL("mcp")`로 정해집니다. 사전 등록이 필요한 서버에는 이 주소를 등록해야 합니다. 브라우저 확장은 클라이언트 비밀키를 안전하게 보관할 수 없어 confidential-client 전용 OAuth 서버에는 직접 연결할 수 없습니다. Google Drive MCP는 별도 Google Cloud 프로젝트와 OAuth 클라이언트 설정이 필요하며 Developer Preview 접근 조건도 적용됩니다. 서버가 확장 출처를 거부하거나 동적 등록을 지원하지 않으면 서버 측 등록 또는 공개 클라이언트 설정이 필요합니다.

**Agent Skills**에서 `SKILL.md` 파일 또는 `SKILL.md`와 텍스트 리소스를 포함한 폴더를 가져옵니다. 설치한 스킬은 확장 로컬 저장소에 보관되고, `task_start`는 작업 설명과 선택적 영어 `skill_keywords`로 후보 4개를 찾습니다. 후보에는 이름·설명만 포함됩니다. 모델은 `search_skills`로 다시 검색하고 `get_skill(id, path?, offset?)`로 `SKILL.md` 또는 스킬 안의 텍스트 리소스를 읽을 수 있습니다. 본문이 한 번의 도구 결과보다 길면 `nextOffset`으로 이어 읽습니다. 압축할 때 요약 공간이 허용하는 범위에서 최근에 읽은 스킬 최대 3개를 문맥 길이의 10% 안에서 앞부분에 보존합니다.

비발디 시작 페이지나 `chrome://` 같은 브라우저 내부 탭에서는 웹페이지 본문에 연결할 수 없어도 `navigate_to_url`, `list_open_tabs`, `switch_to_tab`을 사용할 수 있습니다. 현재 탭에서 HTTP(S) 주소로 이동하거나 새 탭을 열 수 있고, 같은 창의 내부 탭을 포함해 기존 탭으로 전환할 수 있습니다. 본문 읽기·쓰기와 키 입력 도구는 일반 HTTP(S) 페이지가 로드되고 사이트 접근 권한을 받은 뒤에만 실행됩니다. 이동이나 탭 전환 뒤에는 같은 대화 요청 안에서도 새 탭의 로딩과 사이트 접근 권한을 확인한 후 본문 도구가 새 페이지에 연결됩니다. 로딩 대기는 최대 20초이며, 사이트 권한이 없으면 현재 페이지에서 연결하거나 확장의 사이트 접근을 허용해야 합니다.

확장 코드를 다시 빌드한 뒤에는 `chrome://extensions`에서 Qumi의 **새로고침**을 누르고 사이드 패널을 다시 여세요. 이번 manifest 권한 변경으로 브라우저가 모든 사이트 접근을 승인하도록 요청할 수 있습니다. 승인하지 않았다면 확장 관리에서 Qumi의 사이트 접근을 **모든 사이트에서**로 설정해야 자동 연결됩니다.

`send_key`는 연결된 탭에서 현재 포커스된 편집기에 키 또는 텍스트를 보냅니다. 예를 들어 `{ "key": "a", "modifiers": ["Control"] }`로 전체 선택, `{ "key": "Enter" }`로 줄 바꿈, `{ "text": "새 문장" }`으로 유니코드 텍스트 입력을 요청할 수 있습니다. Google 문서처럼 본문이 캔버스로 표시되는 편집기에서는 먼저 편집 위치를 포커스해야 합니다. 도구의 `dispatched` 응답은 브라우저가 입력을 전달했다는 뜻이며, 문서에 반영되거나 저장되었는지는 별도로 확인해야 합니다. 이 기능은 Chrome의 `debugger` 권한을 사용하므로 확장을 다시 로드할 때 권한 경고가 표시될 수 있고, 입력 중 브라우저에 디버깅 표시가 잠시 나타날 수 있습니다.

`capture_screenshot`은 연결된 탭의 현재 보이는 화면을 PNG 이미지로 찍어 다음 모델 요청에 이미지 입력으로 보냅니다. 이미지가 있는 도구 결과는 해당 대화 턴 안에서만 사용하고 로컬 대화 기록에는 이미지 바이트를 저장하지 않습니다. 이미지의 픽셀 좌표를 `mouse_move`, `mouse_click`, `mouse_drag`, `mouse_scroll`에 전달하면 Qumi가 브라우저 화면 좌표로 변환해 입력합니다. 클릭·드래그·스크롤 뒤에는 새 스크린샷을 찍어야 다음 좌표 작업을 할 수 있습니다. 마우스 도구는 웹페이지에 포인터 이벤트를 보내며 운영체제 커서를 움직이지 않습니다. 모델과 Gateway 제공자가 이미지 입력을 지원해야 화면을 해석할 수 있습니다. 현재 Q Gateway의 Codex 어댑터는 이미지 부분을 버리므로 Codex 모델에서는 이 기능을 사용할 수 없습니다. 화면 캡처와 마우스 입력에도 기존 **브라우저 작업 확인** 정책이 적용됩니다.

연속 입력에는 `send_keys`를 사용합니다. 예를 들어 `{ "steps": [{ "key": "a", "modifiers": ["Control"] }, { "text": "새 문장" }, { "key": "Enter" }] }`를 한 번 호출하면 순서대로 입력합니다. 한 호출에 최대 30단계, 텍스트 합계 16,000자까지이며 승인과 디버거 연결은 한 번만 수행합니다. 중간에 실패하면 이후 단계는 실행하지 않습니다. 앞선 단계가 이미 반영되었을 수 있으므로 결과를 확인한 후 다시 시도해야 합니다.

연결된 웹페이지에서 **+ 영역 선택**을 누른 뒤 페이지 위에 스크린샷을 찍듯 사각형을 드래그합니다. Qumi는 해당 사각형과 겹치는 본문 텍스트의 CSS 선택자, 텍스트, HTML 조각을 질문에 첨부합니다. Esc나 **선택 취소**로 중단할 수 있습니다. 한 요청에 최대 5개를 추가하거나 보내기 전에 각각 제거할 수 있습니다. 예를 들어 "한국어로 번역해 줘", "이 문체로 다시 써 줘", "문법을 검사하고 수정해 줘"라고 요청할 수 있습니다. 첨부 내용은 대화 내역에 작은 `<주석 1>` 표시로 남고, 마우스를 올리거나 눌러 펼칠 수 있습니다. 텍스트는 최대 16,000자, HTML은 최대 24,000자까지 포함하며 넘으면 주석에 잘림이 표시됩니다. 첨부한 페이지 내용은 모델 요청과 확장 로컬 대화 기록에 저장됩니다. 스크린샷 이미지는 모델에 전송하지 않습니다.

설정의 **브라우저 작업 확인**은 `모든 작업마다 확인`(읽기 포함), `변경 작업만 확인`(입력·키 입력·클릭·탭 이동), `확인 없이 실행` 중에서 선택합니다. 기본값은 기존 동작인 `변경 작업만 확인`입니다. 이 설정은 Qumi의 작업 확인 창에 적용되며 브라우저의 사이트 접근 설정과는 별개입니다.

실행을 분석하려면 설정의 **실행 진단 로그 → JSON 다운로드**를 사용하세요. 각 대화 턴의 모델 요청, 도구 호출, 압축, 오류와 소요 시간·토큰 수를 `turnId`와 순번으로 묶어 기록합니다. 로그는 Chrome의 확장 로컬 저장소(`qumiExecutionLog`)에 최근 7일, 최대 10,000개 이벤트까지 보관합니다. 프롬프트, 페이지 내용, 도구 인수 값·결과, API 키와 원본 오류 메시지는 기록하지 않습니다. 설정에서 로그를 지울 수 있습니다.

Q Gateway는 기본적으로 임의의 로컬 포트를 사용하므로 확장에 포트를 고정하지 않았습니다. 현재 확장은 `127.0.0.1`과 `localhost`의 HTTP(S) Gateway만 허용합니다. 설정과 대화, API 키는 Chrome의 로컬 확장 저장소에 저장됩니다.

## 개발

```powershell
pnpm install
pnpm dev
pnpm test
pnpm build
```

`pnpm dev`는 UI 미리보기용입니다. Gateway와의 실제 연결은 Chrome에 로드한 `dist` 확장에서 확인하세요. **모델 API**의 기본값은 Chat Completions입니다. 이 방식은 `POST /v1/chat/completions`의 SSE 스트림을 사용하고, 스트림이 지원되지 않으면 일반 JSON 응답을 처리합니다. 완료된 턴의 `conversation_id`와 압축 문맥을 다음 요청에 사용합니다. **Responses**를 선택하면 `POST /v1/responses`를 사용하고, 함수 호출 결과를 `function_call_output`으로 보내며 모델의 출력 항목을 다음 입력에 다시 포함합니다. 이 방식은 해당 Gateway 제공자가 Responses를 기본 지원해야 합니다. 현재 `llm-provider`의 OpenAI 제공자는 Responses를 그대로 전달하지만, Codex 제공자는 Chat 변환 과정에서 함수 호출 문맥을 보존하지 못하므로 Qumi에서 Codex 모델의 Responses 선택을 막습니다. API 방식을 바꾸면 현재 대화는 초기화됩니다. 어느 방식이든 Gateway가 thinking을 스트리밍하면 답변이 시작되기 전까지 사이드 패널에 보여 주고, 최종 답변이 시작되면 숨깁니다. thinking은 사용자에게 보이는 대화 기록에 저장하지 않습니다. 문맥이 한도에 가까워지면 이전 기록을 체크포인트로 요약하고, 전체 대화 기록은 따로 보존합니다.

에이전트 루프는 모든 턴에 `task_start`와 `task_complete`를 제공합니다. 여러 단계나 브라우저 도구가 필요한 작업은 `task_start(objective, completion_criteria?, skill_keywords?)`로 시작하고, 시작한 작업은 단독 `task_complete(outcome, summary, findings?, artifacts?, verification?, blocker?)` 호출로 끝납니다. 짧은 일반 답변에는 두 도구가 필요하지 않습니다. 작업 도중 모델이 일반 답변만 반환하면 루프가 완료 도구를 요청하며 계속 진행합니다. 완료 도구의 구조화 결과가 사용자에게 표시되고, Gateway의 도구 응답 턴도 마무리한 뒤 다음 대화로 넘어갑니다.

`wait({ "time": 2 })`는 2초 동안 기다린 뒤 같은 요청에서 작업을 계속합니다. `time`은 초 단위이며 0보다 크고 최대 120까지 지정할 수 있습니다. 요청을 중단하면 대기도 즉시 취소됩니다.

브라우저 탐색 도구는 요청 시작 시 활성화된 탭에 묶이고, Qumi 도구가 이동·전환한 경우에는 같은 요청 안에서 새 탭으로 대상을 갱신합니다. DOM 도구는 접근 권한이 있는 HTTP(S) 웹페이지에서만 실행됩니다. 사용자 조작으로 탭이나 주소가 예기치 않게 바뀌면 기존 도구 호출은 중단됩니다. 브라우저가 사이트 접근을 보류하거나 철회한 경우에는 자동 연결되지 않으며 수동 **연결**에 사용자 클릭이 필요합니다. `chrome://` 같은 제한 페이지와 교차 출처 iframe은 읽을 수 없습니다. 사각형 영역 선택은 현재 보이는 최상위 문서의 DOM 텍스트를 기준으로 하며 그림자 DOM과 iframe 내부는 포함하지 않습니다. 페이지 읽기는 본문·선택 텍스트·일부 링크를 제한된 크기로 가져옵니다. DOM 도구도 보이는 요소에만 접근하고, 쓰기와 클릭은 대상 CSS 선택자가 요소 하나와 일치해야 합니다. 본문 수정은 직접 자식 텍스트 노드 하나씩 처리하여 하위 요소와 마크업을 보존하며, 페이지가 자체적으로 다시 렌더링하면 수정 내용이 사라질 수 있습니다. 속성 변경은 `id`, `class`, `title`, `role`, `lang`, `dir`, `hidden`, `disabled`, `readonly`, `required`, `placeholder`, `alt`, `tabindex`, `aria-*`, `data-*`에 한정합니다. URL·이벤트 핸들러·스타일 속성과 비밀번호·파일 입력은 쓰지 않습니다. 같은 창의 기존 탭 목록을 보여 주기 위해 확장은 `tabs` 권한으로 탭의 URL과 제목에 접근합니다. 설정과 전체 대화 기록은 Chrome의 `storage.local`에 저장되므로 매우 긴 대화는 저장소 용량 한도에 닿을 수 있습니다.

`scroll_all_text`는 `{ "from": 1, "to": 30 }`처럼 1부터 세는 양끝 포함 범위, `{ "from": 1, "limit": 30 }`처럼 시작 번호와 개수, 또는 `{ "afterSelector": "body > main:nth-of-type(1) > h2:nth-of-type(1)", "limit": 30 }`처럼 지정 요소의 하위 트리가 끝난 뒤부터 읽습니다. 한 번에 최대 50개를 반환하며 각 항목에는 전체 문서 순서의 `index`, `selector`, 해당 요소의 직접 텍스트 노드 번호 `textNodeIndex`, `text`가 들어갑니다. `nextIndex`로 다음 범위를 요청할 수 있습니다. 현재 DOM에 로드된 보이는 텍스트를 읽으며 실제 페이지 스크롤이나 추가 로딩은 하지 않습니다. 긴 텍스트 노드는 4,000자에서 잘리고, 응답이 커지면 `outputLimited`가 표시됩니다.

본문의 여러 텍스트 노드를 바꿀 때는 `dom_write_many`에 `{ "writes": [{ "selector": "body > main:nth-of-type(1) > p:nth-of-type(1)", "textNodeIndex": 0, "value": "새 문장" }] }` 형식으로 최대 20개를 함께 보냅니다. 한 번에 쓸 새 텍스트 합계는 24,000자까지입니다. Qumi가 모든 대상의 기존 텍스트를 읽고 설정에 따른 변경 승인을 받은 뒤, 어느 하나라도 달라졌으면 전체 변경을 취소합니다. `dom_write`는 단일 텍스트 노드·속성·입력값 변경에 계속 사용할 수 있습니다.

개발 스크립트는 Node.js 24 이상에서 확인했습니다.

브라우저 안에서 동작하는 작은 도우미의 남은 기능 범위와 공수는 [에이전트 루프 검토](docs/browser-agent-loop-estimate.md)에 정리했습니다.
