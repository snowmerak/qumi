# Qumi 브라우저 에이전트 루프 범위와 공수

상태: 초기 추정과 구현 현황 · 2026-09-25

이 문서는 Qumi를 브라우저 안에서 동작하는 독립적인 작은 도우미로 발전시킬 때 필요한 TypeScript 에이전트 루프의 범위와 최초 공수 추정을 정리한다. Qumi가 `q remote`에 의존하지 않는 방향은 전제다. Q의 현재 구현(`q` 커밋 `017b599`)을 참고하되, Q의 Go 루프와 주변 서비스를 기능 단위로 복제하는 계획은 포함하지 않는다. 아래 공수는 구현 전 추정치이며 남은 작업량을 뜻하지 않는다. 실제 Gateway·모델 호환성 시험 후 조정한다.

## 현재 출발점과 목표

현재 Qumi는 Chrome MV3 사이드 패널에서 Q Gateway의 `/v1/models`와 스트리밍 `/v1/chat/completions`를 호출한다. TypeScript 루프가 모델 도구 호출과 결과 전달, 턴 상한·취소, 문맥 압축을 처리한다. 전체 대화와 압축 문맥, `conversation_id`를 로컬에 저장한다. 연결한 현재 탭의 URL·제목·본문을 읽고, 사용자가 확인한 URL로 이동하거나 새 탭을 열 수 있다. 현재 코드의 기준은 [`src/gateway.ts`](../src/gateway.ts), [`src/agent.ts`](../src/agent.ts), [`src/page-context.ts`](../src/page-context.ts), [`src/storage.ts`](../src/storage.ts), [`public/manifest.json`](../public/manifest.json)이다.

목표는 **사용자가 선택한 현재 탭의 내용을 읽어 질문에 답하고, 필요할 때 허용된 브라우저 도구를 여러 차례 호출하며, 긴 대화를 압축해 계속 이어가는 작은 도우미**다. 모델 연결에는 우선 기존 Q Gateway를 사용한다. Qumi가 대화·압축 문맥·브라우저 도구 실행을 소유하며 `q remote`, Q의 세션 저장소, 로컬 파일 도구를 요구하지 않는다.

## 이번 구현 상태

- 완료: `/v1/models`의 `context_length` 사용과 수동 설정, SSE 텍스트·도구 호출 조각 결합, JSON 응답 대체, 도구 실행 루프의 허용 목록·오류·상한·취소.
- 완료: 전체 대화와 모델 문맥 분리, 85% 압축 시작·22% 목표·7% 최근 기록, 긴 기록 분할 요약, 이전 사실 병합, 실패 시 이전 문맥 보존, 압축 후 `conversation_id` 초기화.
- 완료: Codex의 이전 `conversation_id`에 해당하는 rollout이 없으면 전체 메시지를 유지한 채 ID를 비우고 한 번 재시도한다. 스트림 응답이 시작된 뒤에는 중복 응답을 피하기 위해 재시도하지 않는다.
- 완료: 마지막 완료 턴의 상태를 하나의 `chrome.storage.local` 항목으로 저장하고 기존 채팅 기록을 읽는 이전 처리. 모의 Gateway 단위 시험과 개발 화면의 SSE 확인.
- 완료: 사이트별 선택적 접근 권한과 `scripting`으로 사용자가 연결한 탭의 URL·제목·선택 텍스트·보이는 본문·일부 링크 읽기. `tabs`로 같은 창의 웹 탭 목록을 확인한다. URL 이동·새 탭 열기·기존 탭 전환은 사용자에게 목적지를 확인받는다. 탭 전환·페이지 로딩 후 연결을 끊는다.
- 남음: 실제 Gateway와 사용할 모델에서 스트리밍·도구 호출·문맥 메타데이터 확인, 실제 Chrome 확장 권한·탭 이동 통합 시험, IndexedDB 저장 이전. 현재 `storage.local`의 기본 용량 한도는 긴 전체 대화에서 제약이 된다.

## Q에서 가져올 동작

| Q의 동작과 참고 위치 | Qumi에 적용할 범위 |
| --- | --- |
| 모델 응답의 `tool_calls`를 순서대로 실행하고 각 `tool_call_id`의 결과를 대화에 넣어 다시 모델을 호출한다 (`q/agentloop/loop.go`). | 필수. 허용된 도구만 실행하고 알 수 없는 이름, 잘못된 인수, 실패를 모델이 읽을 수 있는 도구 오류로 돌려준다. |
| 도구가 끝나거나 일반 어시스턴트 응답이 오면 턴을 종료한다 (`q/agentloop/loop.go`). | 필수. 최대 모델 왕복 수·도구 호출 수·실행 시간을 두고 취소를 전달한다. 브라우저 작업에서는 무한 루프를 허용하지 않는다. |
| 이벤트를 순서대로 소비하고 최종 응답과 모델 문맥을 구분한다 (`q/agentloop/types.go`). | 필수. 사용자에게 보이는 대화와 모델에 보내는 도구 포함 기록을 분리한다. 실행 중 상태는 메모리에 두고 완료된 턴을 체크포인트와 함께 영구 저장한다. |
| 모델 문맥의 사용량을 추정하고 긴 대화를 체크포인트로 압축한다 (`q/memory/manager.go`, `checkpoint.go`, `q/agentloop/context.go`). | **첫 릴리스 필수.** 전체 대화 기록과 압축 문맥을 분리해 저장하고, 압축 후에도 현재 요청·확정된 사실·미완료 작업을 이어간다. 아래 압축 계약을 따른다. |
| 스트림 조각과 도구 인수를 합치고, 빈 응답과 공급자 대화 오류에서 복구한다 (`q/agentloop/chat_stream.go`, `chat_recovery.go`). | 스트리밍과 JSON 응답 대체, 사라진 Codex rollout에 대한 한 번의 새 대화 재시도는 구현했다. 빈 응답에 대한 Q의 추가 복구 정책은 별도로 남아 있다. |
| `task_start`, `ask_to_user`, `task_complete`와 활성 작업 복원 (`q/agentloop/orchestration.go`). | Q 형식 그대로 옮기지 않는다. 사용자 확인은 Qumi UI에서 처리하고, 긴 작업 수명주기는 실제 수요가 생기면 설계한다. |

Q의 별도 Workspace Memory 서비스, Skills, MCP, 서브에이전트, 파일·셸 도구, 복잡한 모델 라우팅은 브라우저 도우미의 첫 범위에서 제외한다. Loom도 가져오지 않는다. **대화 문맥 압축은 이 제외 목록과 무관하며 첫 범위에 포함한다.**

## 제안하는 최소 구조

```text
사이드 패널: 턴 상태·전체 대화·압축 문맥·모델 요청·취소
      ├─ Q Gateway: OpenAI 호환 채팅 + 도구 호출 응답
      └─ Chrome tabs/scripting: 연결한 탭 읽기·확인 후 URL 이동
```

사이드 패널을 실행 중인 턴의 소유자로 둔다. Chrome의 서비스 워커가 꺼졌다 다시 켜져도 루프 상태에 의존하지 않도록 한다. 패널이 닫혀 실행이 끊기면 진행 중이던 턴을 버리고, 마지막으로 완료되어 저장된 턴에서 새 요청을 시작한다.

확장에 `scripting`, `tabs`와 선택적 HTTP(S) 사이트 권한을 선언하고, 사용자가 **연결**을 누르면 현재 사이트의 접근 권한을 Chrome에 요청한다. 허용된 권한은 Chrome에 사이트 단위로 보존된다. Qumi는 연결한 탭을 `tabId`와 URL로 묶고, 탭이나 페이지가 바뀌면 다시 연결하게 한다. `tabs`는 같은 창에 열린 다른 탭의 URL·제목을 모델이 찾는 데 쓴다. 주입한 스크립트는 제목, URL, 선택한 텍스트, 주요 본문, 일부 링크처럼 제한된 구조화 결과만 반환한다. [Chrome permissions API](https://developer.chrome.com/docs/extensions/reference/api/permissions), [Chrome scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting), [tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs).

브라우저 도구는 `get_current_page`, `list_open_tabs`, `navigate_to_url`, `switch_to_tab`, `dom_list`, `dom_read`, `dom_write`, `dom_click`이다. DOM 탐색은 `body`에서 시작해 보이는 직계 자식과 CSS 선택자를 반환한다. 읽기·쓰기·클릭은 선택자가 한 요소와 일치할 때만 실행한다. `dom_write`는 입력값 외에 `attribute`와 문자열 `value`로 허용된 HTML 속성을 변경하고 `null`로 제거한다. 속성의 기존 값과 새 값을 승인 화면에 표시하고 승인 후 기존 값이 바뀌었으면 중단한다. 페이지 텍스트는 외부 자료로 취급하고 지시문으로 승격하지 않는다. 비밀번호 값·숨겨진 DOM은 수집하지 않으며, 페이지와 도구 결과에 크기 상한을 둔다. URL 이동은 HTTP(S) 절대 주소만 허용하고, 탭 전환·클릭·입력·속성 변경은 매번 사용자의 확인을 받는다.

모델 왕복은 압축 문맥과 허용된 `tools`를 Gateway에 보내고, `tool_calls`가 오면 각 호출을 검증·실행해 도구 결과를 문맥과 전체 대화 기록에 넣은 다음 다시 요청하는 형태다. 마지막 일반 응답으로 턴을 확정한다. 현재는 도구 호출을 포함한 전체 기록과 모델 요청용 압축 문맥을 분리해 하나의 `chrome.storage.local` 항목에 보존한다. 전체 기록은 압축 후에도 커질 수 있으므로, 이후에는 IndexedDB에 두고 마지막 완료 턴의 기록·압축 문맥·체크포인트·`conversation_id`를 한 트랜잭션에서 갱신하는 안을 우선 검토한다. Chrome은 `storage.local`에 기본 용량 제한을 두며 확장 페이지에서 IndexedDB를 사용할 수 있다. [Chrome 저장소 문서](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies), [storage API](https://developer.chrome.com/docs/extensions/reference/api/storage).

## 첫 릴리스의 압축 계약

압축은 단순히 앞부분 메시지를 버리는 기능이 아니다. Q의 `memory.Manager`와 `agentloop.Context`를 참고해 다음 동작을 TypeScript로 구현한다.

1. 모델별 문맥 길이를 `/v1/models`의 `context_length` 메타데이터에서 읽고, 제공되지 않는 모델에는 사용자가 문맥 길이를 설정하게 한다. 길이를 모르는 상태에서 압축을 조용히 비활성화하지 않는다. 메시지와 도구 정의의 크기를 보수적으로 추정하고, 응답의 `usage.prompt_tokens`가 있으면 추정 오차를 보정한다. Q의 기본 압축 정책인 문맥 길이의 85%에서 시작, 22%를 목표, 7%를 최근 기록으로 보존하는 비율은 초기값으로 검토한다.
2. 압축 계획에서 시스템 지시, 현재 사용자 요청, 미완료 도구 호출을 정확히 보존한다. 어시스턴트의 도구 호출과 대응 결과는 하나의 단위로 다뤄 메시지 순서가 깨지지 않게 한다. 크기가 큰 페이지 결과는 원문을 무조건 최근 기록에 남기지 않고 요약 대상으로 넣는다.
3. 별도 모델 요청으로 이전 기록과 기존 체크포인트를 `current_request`, `active_work`, `previous_work`, `facts` 네 구간으로 요약한다. 페이지 자료는 출처가 있는 외부 데이터로 취급하고, 페이지 안의 지시문을 Qumi의 지시로 승격하지 않는다. 코드 펜스나 앞뒤 설명이 섞인 JSON도 복구 가능한 범위에서 정규화하고, 이전 체크포인트의 계속 유효한 사실은 새 체크포인트와 병합한다.
4. 요약 결과가 비었거나 파싱할 수 없거나, 보존할 메시지를 포함한 새 문맥이 모델 한도를 넘으면 기존 문맥을 그대로 둔다. 필요하면 압축을 한 번 재시도하고, 계속 실패하면 턴을 안전하게 중단해 사용자에게 알린다. 성공한 압축은 진행 중 턴의 메모리 상태에 적용하고 `conversation_id`를 비워 새 공급자 대화에서 이어간다. 턴이 완료되면 전체 기록·새 문맥·체크포인트·대화 ID를 함께 영구 저장한다. 전체 대화 기록은 삭제하지 않는다.
5. 패널을 다시 열거나 두 번째·세 번째 압축이 발생해도 체크포인트와 최신 문맥을 복원한다. 화면에는 전체 대화를 계속 보여 주되 모델에는 압축된 문맥을 보낸다.

페이지·도구 결과의 크기 상한도 유지한다. 이는 압축을 대체하는 방식이 아니라, 단일 결과가 모델 문맥 전체를 초과하는 상황을 막는 입력 제한이다.

## 공수 추정

가정: Q 코드를 아는 개발자 1명, 기존 React/TypeScript 골격과 Q Gateway 유지, **도구 호출과 문맥 길이를 확인할 수 있는 선택 모델** 1종을 우선 검증, 데스크톱 Chrome MV3, 읽기 전용 현재 탭, 새 디자인 시스템 작업 없음. 문맥 길이는 모델 메타데이터 또는 사용자 설정으로 확보한다. 1 인일은 구현과 해당 단위의 확인을 포함한 작업일이다. 일정의 병렬화나 모델 응답 시간을 뜻하지 않는다.

| 작업 | 추정 |
| --- | ---: |
| 탭 권한, 현재 페이지 추출, 탭 전환·접근 실패 처리 | 2–3 인일 |
| Gateway 도구 호출·문맥 길이·사용량 형식과 모델 호환성 확인 | 2–3 인일 |
| 도구 실행 루프, 인수 검증, 오류, 상한, 취소 | 3–4 인일 |
| 전체 대화와 압축 문맥의 별도 저장, 기존 기록 이전 및 턴 복원 | 3–5 인일 |
| 압축 판단·보존 계획·체크포인트 생성/검증·원자적 교체 | 5–8 인일 |
| 실행 상태·중단·현재 페이지 연결 UI | 1–2 인일 |
| 모의 Gateway, 반복 압축 및 실제 Chrome 통합 검증 | 3–4 인일 |
| **압축 포함 읽기 전용 최소 에이전트 합계** | **19–29 인일** |

구현 전 추정에서 첫 릴리스의 읽기 전용 도구 루프와 압축까지 총 **19–29 인일**, 개발자 1명 기준 대략 **4–6주**로 보았다. 현재 루프와 스트리밍은 구현했으므로 이 수치를 남은 일정으로 사용해서는 안 된다. 실제 모델 호환성, 페이지 도구, 저장 이전, Chrome 통합 검증을 마친 뒤 잔여 공수를 다시 산정해야 한다. 클릭·입력·탐색과 사용자 확인의 최초 추정은 **추가 5–9 인일**이었다.

Q의 작업 수명주기, Skills/MCP/서브에이전트, 저장소·도구 정책까지 폭넓게 맞추는 것은 별도 제품 범위다. 현재 정보로는 **추가 8–16주 이상**의 거친 추정이며, 포함 범위에 따라 더 길어질 수 있다. 이 비용을 작은 브라우저 도우미의 초기 계획에 넣을 이유는 아직 없다.

## 먼저 확인할 위험과 완료 기준

- Q Gateway와 실제 사용할 모델이 `tools` 요청과 `tool_calls` 응답을 끝까지 전달하는지 확인한다. 모델별 차이가 있으면 위 일정에 호환성 작업이 추가된다.
- 일반 웹페이지에서 확장을 눌러 탭을 붙인 뒤 페이지 질문에 답할 수 있어야 한다. 새 도메인으로 이동하거나 접근할 수 없는 탭에서는 이전 페이지를 조용히 재사용하지 않는다.
- 잘못된 JSON 인수, 알 수 없는 도구, 도구 실패, 여러 도구 호출, 사용자의 취소, 패널 종료 후 재진입에서 기록이 손상되거나 실행이 무한 반복되지 않아야 한다.
- 긴 페이지 결과와 여러 턴의 도구 기록으로 압축을 발생시켜도 현재 요청·확정된 사실·미완료 작업이 이어져야 한다. 두 번 이상 압축하고 패널을 다시 열어도 전체 대화와 압축 문맥이 각각 유지되어야 한다.
- 압축 결과가 유효하지 않으면 원래 문맥을 잃지 않아야 한다. 성공한 압축 직후에는 이전 `conversation_id`를 재사용하지 않는다. 문맥 길이를 알 수 없는 모델은 명시적으로 설정할 수 있어야 한다.
- 저장 실패나 패널 종료로 진행 중 턴이 사라져도 마지막 완료 턴의 전체 기록과 압축 문맥은 서로 일치해야 한다. 기존 Qumi 기록을 새 형식으로 이전할 수 있어야 한다.
- 웹페이지에 적힌 명령이 확장 권한을 늘리거나 허용되지 않은 도구를 호출하게 만들지 않아야 한다. 실행 결과와 페이지 내용은 크기 상한 안에 머문다.

이 문서의 추정은 읽기 전용 브라우저 도구와 대화 압축을 첫 목표로 삼는 판단에 의존한다. Qumi가 실제 페이지 조작까지 해야 하는지 정해지면 도구 목록과 권한·확인 흐름을 먼저 확정하고 공수를 다시 산정한다.
